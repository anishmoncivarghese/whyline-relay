# whyline-relay 0.2.4

A role can now name a backup agent, used automatically when the active one hits a usage limit or stops being authenticated — the third of the three pieces the agent-adapters design deferred for its own design session. Built by running whyline-relay on its own plan, with one real defect found and fixed during independent verification before this release.

## New

- **`[roles.backup]`** in `config.toml` names one backup agent for `implementer` or `reviewer`, validated exactly like `[roles]` itself (must be a built-in or a configured generic agent, and cannot name the same agent already filling that role).
- **Two triggers switch a role to its backup automatically, in the same run, with no pause**: a detected usage/rate limit (the existing text-marker check), and a detected loss of authentication (re-running the agent's own login-status command — `codex login status`, `claude auth status` — never guessed from output text). A generic agent has no such command and can never trigger the auth path.
- **The switch is sticky.** Once active, the backup stays the role's effective agent for the rest of that task and every task after, until you change it — no agent measured so far reliably reports when a quota resets, so the relay doesn't guess with a timer.
- **`whyline-relay roles status`** shows each role's configured agent and, if switched, the active one and why. **`whyline-relay roles reset [ROLE]`** reverts one role or all of them.
- **Preflight checks a configured backup too**, on PATH and (for a built-in agent) logged in, labelled as a backup in its message, so a backup that can't run is caught before it's needed rather than mid-plan. An agent that is both someone's primary and someone else's backup is reported once, as the primary it already is.
- If the backup also fails, there's no further fallback: the run pauses, naming both agents and what each one hit.

## Fixed

- **A real defect, found during verification, not in production.** After a switch, the agent's own prompt still told it to record its handoff under the *old* agent's name (`{implementer}`/`{reviewer}` were rendered from the static `[roles]` config, not the agent that was actually running), which the relay's own from-actor check then correctly rejected as a mismatch. Caught by an acceptance test whose stand-in reads the rendered prompt the way a real agent would, rather than being told its from/to actor on the command line — the internal unit tests, which don't inspect the rendered prompt, missed it entirely. Fixed before this code ever shipped; no earlier release is affected, since backups didn't exist before this one.

## Who this affects

Nothing changes for a repository with no `[roles.backup]` — every message, file, and default is exactly what 0.2.3 produced.

## Upgrading from 0.2.3

`uv tool upgrade whyline-relay`. Add `[roles.backup]` to an existing `config.toml` whenever you want it; nothing else needs to change.

## How it was checked

- 350 tests (313 before), on Linux and macOS, Python 3.11 and 3.13.
- 150 existing acceptance tests (97 from earlier releases, 53 from the adapters release), run unedited against the result.
- 17 new independent acceptance tests, written from the plan's requirements before the run: a rate-limited and an unauthenticated implementer each switch and the run completes; the switch is sticky across a second task; a switch never consumes a review round; the backup also failing pauses and names both agents; `roles status`/`reset` round-trip; preflight catches a backup that's missing or not logged in; every `[roles.backup]` validation error; default behaviour is unchanged with no backup configured.
- The from-actor defect above was found by these acceptance tests, not the unit suite — a real demonstration of why the project writes them independently before every round, not after.

## Known issues

- Tested on macOS only. Windows is untested.
- One backup per role, no chain, and no automatic reversion to the primary — the owner reverts by hand with `roles reset`.
- Only `codex` and `claude` are built in. Antigravity/`agy` works today only via the generic adapter.
- No phase gate: use one plan file per phase to get a review point.
- An automated review is lighter than a careful human one. Read the branch before merging.
