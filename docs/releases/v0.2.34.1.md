# whyline-relay 0.2.34.1

Checking for a running relay no longer sends Ctrl+C on Windows.

## What's changed

- **Process liveness on Windows asks the OS instead of signalling.** The
  relay decided whether a recorded process was still running with
  `os.kill(pid, 0)`. On Windows, signal `0` is `CTRL_C_EVENT`, so that check
  interrupted every process on the console, including whyline and the agents,
  whenever it looked at the live-run marker (status, Stop, and the console's
  polling). Windows now uses `OpenProcess` and `GetExitCodeProcess`; macOS
  and Linux are unchanged.
- **CI checks liveness on Windows.** A Windows job runs the liveness tests and
  confirms the current process reads as running without being interrupted.

## Upgrading

```bash
uv tool upgrade whyline
```
