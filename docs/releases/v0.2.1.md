# whyline-relay 0.2.1

Setup problems now show up before a run, not in the middle of it, and the relay can be embedded in another program. Like 0.2.0, these three changes were each implemented by Codex, then reviewed and committed by Claude, by running this tool on its own plan.

## New

- **`whyline-relay doctor`** checks the setup and prints one line per check: a git repository, whyline installed and initialised, the relay set up (including its permissions file), the `codex` and `claude` programs on PATH, both logins (`codex login status`, `claude auth status`), a valid plan with work left in it, a clean working tree, and no other relay running. Each failure comes with the command that fixes it (`codex login`, `claude auth login`, `whyline init --yes`, ...). It exits 1 if anything fails, and reports warnings without failing, for example a task written without an `ID:`, whose id would silently be its first word.
- **A preflight on `start` and `resume`.** They run the same checks first and refuse, before launching an agent or touching the repository, if one fails. `--skip-checks` bypasses it. `start --dry-run` runs none of it and never calls a login command.
- **`whyline-relay plan-format`** prints how to write a plan and a short paste-ready prompt for an AI that is drafting one (`--prompt` prints only the prompt). It needs no repository. A test parses the example inside the prompt with the real plan parser, so the documentation cannot drift from it.
- **Embedding.** `whyline_relay.cli.main(argv=None, prog="whyline-relay")` is now the supported way to run the relay from another program. Every hint the relay prints (`Resume with: ...`, the refusals, the fix hints) uses the name it was called by, and a test forbids a hard-coded `whyline-relay <command>` from creeping back into the source. This is groundwork for running the relay as `whyline relay <command>` from whyline itself.

## Changed

- The refusals when another relay is live now also say to run `stop` first.
- README: a Quick start step for `doctor`, "Having an AI draft the plan", and "Using it from another program".

## Upgrading from 0.2.0

`uv tool upgrade whyline-relay`. Nothing needs to change in your repositories. The new preflight may warn about tasks in your plan that have no `ID:`; it does not block on those.

## How it was checked

- 237 tests, on Linux and macOS, Python 3.11 and 3.13, with fake agents only. The preflight's external commands (`whyline sync` and the two login commands) go through an injectable runner, so the suite never launches a real `codex`, `claude` or `whyline`.
- 97 independent acceptance tests, written from the requirements before the run and run through the command line against the real relay, with `codex` and `claude` stand-ins on PATH that could be logged in or out.
- Three real tasks, one round each, on `codex-cli 0.155.1` and Claude Code `2.1.278`.

## Known issues

- Tested on macOS only. Windows is untested.
- No phase gate: use one plan file per phase to get a review point.
- An automated review is lighter than a careful human one. Read the branch before merging.
