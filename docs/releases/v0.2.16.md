# whyline-relay 0.2.16

`whyline-relay chat` — a new interactive REPL where free text goes to a fixed default agent, `/claude`/`/codex`/`/agy`/`/grok` targets one directly, and every agent shares one conversation history for the repo, including across full agentic turns (edits, commands, commits). Typing bare `whyline` (0.3.5) now starts this directly.

## What's new

- **`whyline-relay chat`**: an interactive REPL. First run detects which of claude/codex/agy/grok are installed and asks you to pick a default (`/default <agent>` changes it later). Plain text goes to the default agent; `/claude`, `/codex`, `/agy`, `/grok` sends one message to a specific agent without changing the default. Meta-commands: `/agents`, `/history`, `/clear`, `/exit`.
- **Full agentic turns, under each agent's existing permission floor.** claude and codex always work in chat, even with zero `config.toml` in the repo, using their own managed defaults — `bypass.py`'s guard and every existing permission safeguard apply unchanged. `agy`/`grok` only work in chat if they're already configured as a generic agent (the same README recipes documented for the relay's task loop); chat never invents a separate, looser permission set.
- **Shared, capped conversation history** (`.whyline/relay/chat-history.jsonl`, gitignored): switching agents mid-conversation doesn't lose context — every new turn's prompt includes the capped, verbatim tail of the transcript so far.
- **A turn that changes files is committed automatically** (`chat: <agent> turn`), with the diff-stat printed right after so you always see what changed before typing your next line.
- **`agents.run()` gains `capture`**, returning a new `RunResult(exit_code, output)` instead of a bare int — buffers a turn's output for the response to be extracted, without echoing it raw to the terminal (the existing heartbeat status lines are unaffected). Each `Adapter` gains `extract_response`/`uses_output_file` to pull a clean final answer out of a turn: claude's existing `--output-format json` already carries a `result` field; codex uses a real `-o`/`--output-last-message` flag; a generic agent tries `result`/`response`/`text`/`message` in order (verified directly against real `agy`/`grok` output, which use different field names from each other and from claude).
- **`init`'s `.gitignore` also covers chat's own state files** (`chat.json`, `chat-history.jsonl`), via a new shared `init.ensure_relay_gitignore`, callable from both `init` and chat's own first-launch setup — whichever runs first produces a correct file.

## How it was checked

- 552 tests (549 before this release's own final fix; 500 before the chat feature).
- Built with Grok as implementer and Codex as reviewer via whyline-relay itself — the most substantial piece built this way to date (8 tasks, one review round requesting changes). Grok's own turns were correct on every task, but it got cancelled before calling `whyline handoff` on 11 of 12 total turns — this project's `pytest -q` doesn't print a "N passed" summary line, and Grok's own habit of re-checking for it caused repeated stalls. The orchestrator (Claude) independently verified every turn's diff and the full suite before committing and handing off on Grok's behalf.
- Codex's review caught one real defect a mocked test suite alone had missed: `run_turn` silently dropped the persisted chat record's `timestamp` field, returning a differently-shaped dict than what `chatlog.append` actually wrote. Fixed by having `chatlog.append` return the record it persists, and `run_turn` build on that directly.
- Grok itself independently found and correctly fixed two further gaps neither the design spec nor the plan anticipated: a golden-output/docstring conflict with `init`'s own regression tests, and a hardcoded-relay-command literal (`whyline-relay doctor`) that would have broken this CLI's ability to be embedded under a different program name — fixed via the existing `invocation.command()` abstraction instead.
- **A real, empirically-found bug, caught only by running an actual end-to-end chat session against the real `claude` CLI** (not just the mocked test suite): claude's managed default command references `.whyline/relay/claude-settings.json`, which only `init` used to create — so a repo that only ever ran `chat` made the real claude CLI fail outright with "Settings file not found." Fixed: chat now generates that file itself on first use (identical content to what `init` would write), committed separately from the turn itself so a turn's own diff-stat reflects only what the agent did. Verified again afterward with a second real chat session (and separately with codex, which needs no such file).

## Known issues

Same open risks as every generic-agent recipe already documented: `agy`/`grok` have no non-interactive login-status check, and denial detail is generic (`stopReason: "cancelled"`, no command/path named). A logged-out or first-run generic-agent session in chat might hang rather than fail promptly, for the same reason.
