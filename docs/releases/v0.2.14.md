# whyline-relay 0.2.14

`init`'s wizard and `roles set`'s interactive prompt now read whyline's own `.whyline/model.json` (from whyline 0.3.2) and pre-fill the "Model for `<agent>`" question with whatever you already set there, instead of always starting blank. `doctor` also gives Antigravity a specific, actionable warning instead of the generic one every other `generic` agent gets.

## New

- **`init`/`roles set` pre-fill the model prompt** from `.whyline/model.json`, if whyline has one for that agent — the same bracketed-default shape `_ask_agent` already uses (`Model for codex [gpt-5-codex] (blank to accept, or type another):`). whyline-relay never writes to this file; `whyline model` is its only writer, so ownership never contends. Both functions behave byte-for-byte as before when the file is absent, corrupt, or has no entry for that agent.
- **`doctor` names Antigravity specifically** when it's configured as a `generic` agent, instead of the generic "the relay does not manage its permissions, login or denials" message: it now points directly at the README's "Using Antigravity today" section and [google-antigravity/antigravity-cli#548](https://github.com/google-antigravity/antigravity-cli/issues/548), since headless permission enforcement there is confirmed unreliable for narrow scopes.
- **README** links issue #548 as corroborating evidence for the machine-global-wildcard finding already documented there.

## Who this affects

Nobody who doesn't have `.whyline/model.json` in their repo (a new whyline 0.3.2 feature) — the prompt is unchanged for everyone else. Anyone who configures Antigravity as a `generic` agent gets a more specific `doctor` warning; the underlying behavior is unchanged.

## Upgrading from 0.2.13

`uv tool upgrade whyline-relay`. Nothing to do.

## How it was checked

- 488 tests (473 before).
- Built with Antigravity as implementer and Codex as reviewer — the second piece built this way, again with zero pauses across all 3 tasks, under the same accepted-risk global permissions wildcard documented in this README.
- Cherry-picked tree diff-verified byte-for-byte against the sandbox before merging.
- The existing generic-agent warning test (using "aider", not Antigravity) is unaffected — confirmed it still gets the original, unmodified message, proving the new Antigravity-specific branch doesn't change behavior for any other generic agent.

## Known issues

Same as 0.2.13. Antigravity's headless-mode permission enforcement remains unreliable for narrow scopes (issue #548); the machine-global wildcard documented in "Using Antigravity today" remains the only verified workaround.
