# whyline-relay 0.2.0

The first release built with the relay itself. The nine tasks behind it (`remove`, `--version`, help text, progress lines, a truthful `status`, verified reviews, blocked questions, and a safe `init`) were each implemented by Codex, then reviewed and committed by Claude, by running this tool on its own plan.

## New

- **`whyline-relay remove`** takes the relay out of a repository: it deletes `.whyline/relay/` and the relay's lines from `.git/info/exclude`, after listing what will go and asking. It refuses while a run is paused (`--force` overrides) or live (nothing overrides), never follows a symlink out of the repository, and never commits.
- **Progress lines.** The relay now says what it is doing: `[13:06:44] ==> codex: implementing APP-1 (round 1 of 3)`, `<== claude finished in 1m12s`, and a `... still running` heartbeat after 30 seconds of silence (`WHYLINE_RELAY_HEARTBEAT_SECONDS` changes it). Claude's turn used to be silent until it ended.
- **`status` tells the truth.** While a run is live it prints `Running: claude reviewing APP-1, round 1, since 13:06:49 (2m ago)`. Before, it said "No relay run in progress" during a normal run. A live run is recorded in `.whyline/relay/running.json`, and `start`, `resume` and `remove` refuse to start while another relay is running in the same repository.
- **`--version`**, and a one-line description on every command-line option.
- **`init --overwrite`.** `init` no longer overwrites files you have edited: it keeps them and says so. `--overwrite` replaces them on purpose.

## Changed

- **Reviews fail closed.** The review prompt now tells Claude to run the project's tests itself with the plain test command, and not to approve on the implementer's word: if a command is denied it hands off `blocked` and names the command. In a real run before this change, a review approved without running the tests, because it copied the implementer's `UV_CACHE_DIR=... uv run pytest` command and the allowlist denied it.
- **A blocked pause shows the question.** `Paused: claude reported blocked: cannot run tests. Question: Allow Bash(uv run pytest:*) ...`. The question is also in `status` and the notification (300 characters at most).
- **Wider default permissions:** `tail`, `head`, `wc`, `grep`, `ls`, and for Python `.venv/bin/pytest` and `.venv/bin/python`. The deny list is unchanged.
- **A detailed README.**
- `remove` handles a stray file at `.whyline/relay` instead of crashing.

## Upgrading from 0.1

`uv tool upgrade whyline-relay`. Repositories keep the files `init` wrote under 0.1, so they do not get the new review prompt or permissions until you re-run `whyline-relay init --overwrite` (copy your edits aside first) or apply the two changes by hand. The README's "Upgrading from 0.1" section has the steps.

## How it was checked

- 196 tests, on Linux and macOS, Python 3.11 and 3.13, with fake agents only. The suite never launches a real `codex` or `claude` and never pops a desktop notification.
- For each task, an independent set of acceptance tests written from the task's requirements before the run, and run against the result. 69 in all, run through the command line against the real relay with the real `whyline`.
- Nine real tasks, one round each, on `codex-cli 0.155.1` and Claude Code `2.1.278` on macOS: 31k to 96k Codex tokens and $0.15 to $0.26 of Claude per task.

## Known issues

- Tested on macOS only. Windows is untested.
- No phase gate: use one plan file per phase to get a review point.
- Claude's own turn prints nothing until it ends; the heartbeat shows it is alive.
- An automated review is lighter than a careful human one. Read the branch before merging.
