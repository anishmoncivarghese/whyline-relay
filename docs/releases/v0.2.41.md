# whyline-relay 0.2.41

Named document kinds, so tools built on the planner can draft and review a PRD, a design doc or a build record the way specs are drafted today. Nothing changes for plans or specs.

## What's changed

- **Document kinds are public.** `DocKind` names a document's draft file, checkpoint and prompts. `DocKind.named("prd")` builds one, and each name keeps its own checkpoint, so several kinds can be in progress at once. (RDOC-1)
- **Three new built-in kinds, each with draft and review prompts:**
  - **PRD**: what and why, with numbered requirements, reviewed for testability
  - **Design**: for an architect, with decision records and the options considered
  - **Build record**: written only from the attached inputs, and checked against them

  You can override any prompt with `.whyline/relay/prompts/<kind>-draft.md` or `-review.md`. (RDOC-1)
- **A `documents` module** with `draft`, `revise`, `answer`, `resume_draft`, `discard` and `pending_description` for any kind. (RDOC-1)
- **Templates.** `draft(..., template=…)` gives the writer a fixed structure to follow. It is kept in the checkpoint, so revise and resume keep it too. (RDOC-2)
- **Revise a given text.** `documents.revise_text(...)` starts from existing text, for example a document a person has edited or approved earlier, and runs the usual revise and review loop on it. For a plan with a Test planner, the test plan is regenerated so it stays in step. (RDOC-2)

These are what the whyline console's upcoming document pipeline uses (agentdock `plans/sdlc-pipeline.plan.md`).

## Upgrading
