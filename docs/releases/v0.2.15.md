# whyline-relay 0.2.15

`doctor` now gives Grok (xAI's "Grok Build" CLI) a specific, actionable warning when it's configured as a `generic` agent, and the README documents a real, empirically verified generic-adapter recipe for it — mirroring the existing Antigravity section.

## New

- **`doctor` names Grok specifically** when it's configured as a `generic` agent, instead of the generic "the relay does not manage its permissions, login or denials" message: it now points directly at the README's "Using Grok today" section, since there is no non-interactive login-status check or specific denial detail for it, the same two gaps Antigravity has.
- **README documents a verified Grok recipe**: real per-invocation `--allow`/`--deny` rules, `--permission-mode dontAsk` (deny-by-default), and the same trailing-`-p` ordering constraint Antigravity's own recipe has (the relay always appends the prompt as the command's final argument). Verified directly: a full realistic implement turn (edit, create a new file via `Edit` alone, run verification, `whyline note`, commit) and a full realistic reviewer turn (accurate diff summary) both completed correctly, and an explicit `--deny` rule beat a broader `--allow` for the same command even against a permissive `.claude/settings.local.json`.
- `bypass.py`'s binary-name-based guard (shipped in a prior, independent fix this cycle) already covers `grok` configured this way — nothing new to change there.

## Who this affects

Nobody who doesn't configure Grok as a `generic` agent — behavior for every other agent, including Antigravity's own specific warning, is unchanged (confirmed by a regression test using a third generic agent, "aider", which still gets the original, unmodified message).

## Upgrading from 0.2.14

`uv tool upgrade whyline-relay`. Nothing to do.

## How it was checked

- 498 tests (488 before).
- Built with Antigravity as implementer and Codex as reviewer — the third piece built this way, again with zero pauses across both tasks.
- Cherry-picked tree diff-verified byte-for-byte against the sandbox before merging.
- Grok's own suitability was de-risked beforehand via a 3-way independent consultation (Grok proposing its own adapter design, Codex and Antigravity each independently reviewing it) that converged on "generic recipe, not managed adapter" — see `docs/superpowers/specs/2026-09-26-grok-generic-recipe-design.md` in whyline's own repo.

## Known issues

Grok has no non-interactive login-status check (`grok login` unconditionally starts a live device-code OAuth flow) and denial detail is generic (`stopReason: "cancelled"`, no command/path named) — the same two gaps that keep Antigravity a generic agent too. A logged-out or first-run session might hang rather than fail promptly; this is documented as a known, unverified risk in the README, not assumed safe.
