# whyline-relay 0.2.11

`whyline-relay roles set <ROLE> [--agent NAME] [--model NAME]` permanently points a role at an agent — a real edit to `config.toml`, unlike `roles reset`, which only clears a temporary failover switch. Called with no flags, it prompts interactively. Along the way, a real pre-existing gap is fixed: `roles status` and `roles reset` were both hardcoded to the fixed `implementer`/`reviewer` pair and silently didn't work for a configured `[pipeline]`'s own role names. Built by running whyline-relay on its own plan.

## New

- **`whyline-relay roles set <ROLE> [--agent NAME] [--model NAME]`**: works for any role the current config defines — the legacy pair, or a configured `[pipeline]`'s own roles. Refuses an agent name that isn't a built-in or an already-configured one, the same validation `config.toml` itself is held to. `--model` only applies to a literal built-in agent name (`codex` or `claude`).
- **`roles status`/`roles reset` are pipeline-aware.** Before this release, both silently assumed the fixed `implementer`/`reviewer` pair even when `[pipeline]` was configured — `roles reset` would flatly refuse any of a pipeline's own role names (`tester`, or whatever a profile defines), and `roles status` would show the wrong two names entirely. Both now derive their role list from `roles.current_roles()`, the pipeline's own roles when one is configured.
- `config.toml` is edited with a minimal, targeted text change, not a TOML-writing library — the project has zero runtime dependencies. Only the one `[roles]` line (and, if `--model` is given, one `[agents.<name>]` line) that actually changes is touched; every other line, comment, and table's ordering is preserved exactly.

## Who this affects

Nobody who never runs `roles set`. `roles status`/`roles reset` are unaffected for a config with no `[pipeline]` table — `current_roles()` returns the identical `implementer`/`reviewer` pair those functions always built inline.

## Upgrading from 0.2.10

`uv tool upgrade whyline-relay`. Nothing to do.

## How it was checked

- 438 tests (421 before).
- The full acceptance battery re-run unedited: 207 relevant tests pass, the only two non-passes being an out-of-scope suite and one pre-existing baseline failure already confirmed to fail identically on unmodified 0.2.10.
- 9 new independent acceptance tests, written and validated against a hand-built reference implementation *before* this plan was ever handed to Codex: `roles set` changing an agent and a model, refusing an unknown agent and an unconfigured role, `roles reset` accepting and rejecting role names correctly for both the legacy pair and a configured pipeline, and a specific regression check that `--agent` alone never blocks on a prompt.
- One real design bug was caught during that empirical verification, before the plan was written: an explicit `--agent` with no `--model` was still triggering an interactive model prompt on a built-in agent, which would hang a scripted or CI invocation. Fixed so only a fully-interactive call (no `--agent` given at all) prompts for a model.
- The text-based `config.toml` upsert was proven against 8 real config shapes (no `[roles]` table yet, an existing table with one role, a role already set, a pipeline's own role names, `[roles]` as the last table in the file, an existing `[agents.*]` block with and without a prior `model` key) and re-parsed with `tomllib` each time to confirm the result is valid, correct TOML, not just plausible-looking text.
- The run paused once, for `.whyline/decisions.md` being left out of the reviewer's own commit — not a code defect; committed separately and resumed cleanly with no duplicate work.

## Known issues

Same as 0.2.10, minus what this release fixes, plus: `init` asking about every role's agent and model interactively when setting up a new repository (the other half of spec D11) is a separate, later piece — `roles set` covers changing a role's agent after the fact, not authoring one from scratch. `roles set` also does not add a new role or pipeline stage; it only repoints an existing one.
