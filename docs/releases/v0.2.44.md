# whyline-relay 0.2.44

`doctor`, `start` and `resume` no longer crash with `File name too long` when Antigravity holds a role.

## What's changed

- **The setup check no longer crashes on Antigravity's settings.** In 0.2.42 and 0.2.43, `whyline-relay doctor`, `start` and `resume` stopped with `OSError: File name too long` in any repository where Antigravity held a role. Antigravity's built-in command passes its settings as JSON text after `--settings`, and the setup check tried to open that text as a file. The check now tells the two apart: JSON text is checked as JSON, and a file path is checked as a file. A value that is neither is reported as one failed check with the reason, for example `--settings is not valid JSON` or `--settings is not a usable path`. Upgrading fixes this in every repository, with no change to your config. (PFS-1)
- **One broken check never stops the others.** Each preflight check now runs by itself. If one of them hits an unexpected error, it is listed as a failed check with the error, and the remaining checks still run and report. Before, a single error ended `doctor` with a traceback and showed none of the results. (PFS-2)

## Upgrading

```bash
uv tool upgrade whyline-relay
```

If you use it through whyline:

```bash
uv --no-cache tool upgrade whyline --upgrade-package whyline-relay
```
