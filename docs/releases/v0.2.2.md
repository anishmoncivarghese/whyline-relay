# whyline-relay 0.2.2

Either role, implementer or reviewer, can now be filled by any built-in agent, or by another headless tool you configure yourself. Nothing changes for an existing setup: the defaults are still Codex implementing and Claude reviewing, and every existing configuration keeps working with no edits. Like the releases before it, this one was built by running whyline-relay on its own plan, with each of its nine tasks implemented by Codex, then reviewed and committed by Claude.

## New

- **`[roles]` in `config.toml`** chooses which agent fills which role: `implementer = "codex"` and `reviewer = "claude"` are the defaults and need not be written. Swap them, or put the same agent in both roles (`doctor` then warns the review is not independent, but does not stop you).
- **A `generic` adapter** lets you configure any other headless command as an agent, run the same way as the built-ins: with the prompt appended as its last argument. It must be named explicitly, with `adapter = "generic"` and a `command`; there is no default and no silent fallback. The relay does not manage a generic agent's permissions, login, or how it reports a denial, and says so.
- **`whyline-relay init --implementer NAME --reviewer NAME`** (built-in names only) sets `[roles]` at setup time, and writes permission files only for the agents actually in use, so an all-Codex setup writes no `claude-settings.json`.
- **Provenance follows the real agent.** A handoff and a `whyline note` now record whichever agent's own name is filling the role (`--from gemini --to claude`, for instance), not a fixed `codex`/`claude`. The relay checks this: a handoff recorded under a different name than the agent that just ran pauses the run rather than being accepted.
- **`doctor` reports on non-default setups**: one summary line per role once the roles are not the defaults, a warning when one agent fills both roles, and a notice for a generic agent explaining what the relay does not manage for it. With the default roles, `doctor` output is unchanged.
- **Bypass flags are refused for whichever agent carries them**, not only the two fixed names, including Claude's `--permission-mode bypassPermissions` (not previously checked). The refusal is enforced in the loop itself as well as in `doctor` and `start`, so `--skip-checks` cannot let one through.

## Fixed

- The one-relay-per-repository guard read a live marker written for any agent but `codex` or `claude` as "no relay running", so a second relay could have started under a non-default configuration. Found and fixed before release; no released version other than this fix has been affected, since no earlier version supported another agent name.

## Changed

- Prompt templates use `{implementer}` and `{reviewer}` placeholders instead of literal names, so they stay correct after `[roles]` changes. Existing templates keep working unedited while the roles are left at their defaults; changing `[roles]` on an older setup needs `init --overwrite`, and `doctor` will tell you if you forget.
- The implementer's log file gains a `-implementer` or `-reviewer` suffix when one agent fills both roles, so the two turns don't share a file.
- README: a new "Choosing which agent fills each role" section, and the safety, configuration, command reference and FAQ sections updated throughout.

## Upgrading from 0.2.1

`uv tool upgrade whyline-relay`. Nothing needs to change in your repositories: a `config.toml` with no `[roles]` behaves exactly as before.

## How it was checked

- 311 tests (237 before), on Linux and macOS, Python 3.11 and 3.13, with fake agents only. (Corrected 2026-09-22: the number originally published here, 260, was wrong — verified now by running the actual test suite at the v0.2.1 and v0.2.2 tags rather than trusting a number carried over mid-release.)
- 97 existing independent acceptance tests, run unedited against the result.
- 53 new independent acceptance tests, written from the plan's requirements before the run: swapped and shared roles, a generic agent in either role, the from-actor check, every refused bypass-flag form, preflight checking only the agents in use, and five tests comparing the new code's default output to 0.2.1 byte for byte (init's files and stdout, the assembled prompts, `doctor`'s output).
- Nine real tasks, one round each, on `codex-cli 0.155.1` and Claude Code `2.1.278`.

## Known issues

- Tested on macOS only. Windows is untested.
- Only `codex` and `claude` are built in. A Gemini adapter needs its own measured, signed-in run before it can be added; none exists yet.
- No phase gate: use one plan file per phase to get a review point.
- An automated review is lighter than a careful human one. Read the branch before merging.
