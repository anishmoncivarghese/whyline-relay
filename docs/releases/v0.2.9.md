# whyline-relay 0.2.9

For a configured `[pipeline]`, the relay itself now makes the one commit that finishes a task — no stage, including the terminal one, may commit anymore. This removes an entire class of bug (a committing agent's own judgment being wrong) rather than only guarding against it. Legacy (no `[pipeline]`) is untouched: the reviewer keeps committing exactly as it always has. Built by running whyline-relay on its own plan.

## New

- **`gitcheck.commit_all(root, message) -> bool`**: stages everything and makes one commit, or does nothing and returns `False` if there's nothing to commit.
- **No stage in a configured pipeline may commit, ever** — the HEAD-check every stage's turn was already held to now applies uniformly, including the terminal stage. A stage that commits anyway is paused with a clear message and an exact `git reset` recovery command.
- **The relay makes the finishing commit itself**, once the terminal stage hands off its accepted outcome: it stages everything, builds the message from that handoff's `--summary` plus the task id, and commits. Every configured-pipeline stage's rendered prompt now carries an explicit notice not to commit, even if its own instructions say to — a safety net that can't be forgotten by whoever writes a custom prompt.
- **Crash-safe across the approval-to-commit boundary**: the relay checkpoints an `"@complete"` marker in `state.json` *before* making its own commit. A crash between approval and commit resumes straight to retrying the commit — no agent runs again, and the approval is never silently lost.

## Who this affects

Nobody without a `[pipeline]` table. Legacy's `_run_task` and `_approved` are untouched; `_run_agent` gained one new optional, defaulted parameter that legacy's call site never passes.

## Upgrading from 0.2.8

`uv tool upgrade whyline-relay`. Nothing to do — a configured pipeline's terminal-stage prompt (built-in or custom) no longer needs its own commit instructions; the relay handles it regardless of what the prompt text says.

## How it was checked

- 415 tests (409 before). Three inherited from 0.2.8's own configured-pipeline work were rewritten in place, not dropped: they simulated the terminal stage committing itself, which was correct then and is exactly the bug this release closes.
- The full acceptance battery re-run unedited: 193 relevant tests pass, the only two non-passes being an out-of-scope suite and one pre-existing baseline failure already confirmed to fail identically on unmodified 0.2.8.
- 5 new independent acceptance tests, written and validated against a hand-built reference implementation *before* this plan was ever handed to Codex: the relay making the finishing commit (proven by a shim that never calls `git commit` itself), a terminal-stage self-commit being refused, and a genuine crash-between-approval-and-commit that resumes with zero agent invocations.
- The crash-safety property was the one genuinely new design risk, and was proven correct in a scratch copy against real handoff records before a line of the plan was written — the same discipline as every release since 0.2.6.
- The run itself paused once, for a Claude usage-limit hit mid-review rather than any defect: the commit it had already made was correct, and `resume` recovered cleanly with no duplicate or conflicting commit.

## Known issues

Same as 0.2.8, minus what this release fixes, plus: the relay-generated prompt "protocol footer" from the N-roles design's later section (structured stage/role/recipient/outcome information, rather than one plain-text notice) is still a separate, later piece — this release ships only the one sentence that piece actually needed (telling an agent not to commit).
