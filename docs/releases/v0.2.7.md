# whyline-relay 0.2.7

No user-visible feature. This release is the foundation the next several releases build on: `routing.decide()` — the entire state machine — now runs on a new, general `Role`/`Stage`/`Profile` engine instead of two hard-coded roles, with every existing behavior, message, and file exactly as 0.2.6 produced them. Built by running whyline-relay on its own plan.

## New

- **`whyline_relay.pipeline`**, a new internal module: `Role`, `Stage`, `Profile`, `Pipeline`, `Decision`, and `decide()` — a pure state machine that can express any number of named stages with their own outcome vocabulary and rejection targets, not just today's fixed implementer/reviewer pair. Not wired into `config.toml` yet; there is no way to configure a custom pipeline in this release.
- **`routing.decide()` is now a thin wrapper** over `pipeline.compile_legacy()` and `pipeline.decide()`. Its public names, its signature, and every one of its return values are unchanged.

## Who this affects

Nobody, directly. `loop.py` and `config.py` were not touched at all — confirmed byte-for-byte identical to 0.2.6 before this was cherry-picked in. `tests/test_routing.py`'s 15 tests pass completely unedited, which is the actual proof this is behavior-preserving rather than merely similar-looking.

## Upgrading from 0.2.6

`uv tool upgrade whyline-relay`. Nothing to do.

## How it was checked

- 378 tests (362 before). Critically, the *entire existing suite is unedited* — this release's regression net is that nothing needed to change to keep passing.
- 178 existing acceptance tests, run unedited against the result.
- 7 new independent acceptance tests: real end-to-end relay runs proving nothing broke (these pass on 0.2.6 too, by design — they exist to prove the refactor is safe), plus tests at the Python-API level (the only level this piece has yet) proving `pipeline.py` exists with the designed API, that `routing.decide()` genuinely delegates to it rather than sitting unused beside it, and that the engine can express a real three-stage pipeline — rejecting to a named stage other than "the start," something the old two-constant system had no way to represent — that today's `config.toml` still can't configure.
- The one real design decision this plan's author had to make, verified empirically before writing the plan: `routing.decide()` has never known which agent's turn just ended, only `(status, to_actor)`. The compiled legacy pipeline gives both of its stages the identical transition table for exactly this reason — giving them different tables looked more "correct" but would have been a behavior change, not a refactor. Confirmed by building the real code and running the real suite before finalizing the plan, not by reasoning about it alone.

## Known issues

Same as 0.2.6. `[pipeline]` configuration, crash-safe stage resume, profiles, relay-side commits, and the tester/security-review stages are all separate, later pieces of the same design (`docs/superpowers/specs/2026-09-23-relay-n-roles-design.md`), not yet built.
