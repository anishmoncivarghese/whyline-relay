# whyline-relay 0.2.38

Plans can now carry a reviewed test plan, automate their verification, and
hold a release until its remaining manual checks are explicitly confirmed.
Provider overloads and operational failures also pause or fail over more
cleanly.

## What's changed

- **Optional test planning.** Set `[planner] test` to an agent to have it write
  `<plan>.tests.md` beside a plan created from either a plain request or a
  brainstorm. The Reviewer reviews the plan and test plan together. Leaving
  the Test planner unset preserves the existing planning flow.
- **Verification is part of the plan.** Each planned phase ends with a
  `relay-profile: verify` task that automates and runs the scenarios assigned
  to it. A release task waits for any remaining manual scenarios, which you
  confirm with `whyline relay manual` before publishing.
- **Transient overloads use a one-turn backup.** Capacity, overloaded, busy,
  and HTTP 503 failures hand only the failed turn to the next backup instead
  of creating a sticky role switch. Quota responses including
  `RESOURCE_EXHAUSTED` and code 429 now count as usage limits.
- **Setup and storage failures stop cleanly.** A setup-only configuration
  commit made during a task no longer pauses the relay, and a full disk or
  exhausted quota pauses with an actionable message instead of a traceback.

## Upgrading

```bash
uv tool upgrade whyline-relay
```
