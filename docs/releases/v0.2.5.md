# whyline-relay 0.2.5

One `doctor` messaging fix, found by re-running the exact real-world scenario used to verify 0.2.4 — after 0.2.4 was already published.

## Fixed

- **`doctor`'s per-role summary line labelled a backup-only agent as if it were the current primary.** `ok implementer: claude ...` / `ok reviewer: codex ...` come from a loop that derived the role purely from `agent == roles.implementer`; it never checked whether `agent` was actually a primary or only a configured backup. With non-default roles and a backup naming a third agent that isn't already a primary, that agent printed as `reviewer: codex`, implying it was currently reviewing, when it was only available as a backup. It now prints `reviewer backup: codex`. Nothing about routing or safety was ever wrong — the relay always used the correct agent — this was only what `doctor` said about it.

## Who this affects

Only setups combining **non-default `[roles]`** with a **`[roles.backup]` naming an agent that isn't already a primary**. Default roles print no summary lines at all (unaffected); a backup that's also already a primary was already labelled correctly (as the primary it is).

## Upgrading from 0.2.4

`uv tool upgrade whyline-relay`. Nothing to change.

## How it was checked

- 351 tests (350 before).
- Found and reproduced manually against the published 0.2.4 wheel, then a regression test added (`test_the_summary_line_labels_a_backup_as_a_backup_not_a_primary`) confirming it fails on the old code and passes on the fix.
