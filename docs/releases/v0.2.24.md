# whyline-relay 0.2.24

Brainstorm no longer commits work that isn't its own.

## Fixed

- **Brainstorm commits only brainstorm files.** Every brainstorm turn used
  to finish with `git add -A`, so running a brainstorm while other work was
  uncommitted swept that work into commits titled "brainstorm: <agent>
  independent research on …". This happened for real in whyline's own
  repository. Each stage (research, merge, review, relabel, final synthesis,
  plan draft) now commits only the brainstorm's own files: the per-model
  notes, the shared `docs/brainstorm/<topic>.md`, its tracking files and the
  plan draft. Your other changes stay uncommitted, and so does anything an
  agent writes outside its brief.
- **Generating an agent's permission file commits only that file.** The
  one-time "chat: generate claude's permission settings" commit also used
  `git add -A`, so it could sweep in unrelated work the same way.
- `gitcheck.commit_paths` now reports whether it committed, and skips a path
  that was never written instead of failing the whole commit.

Ordinary chat turns still commit what the agent changed: there, the agent's
edits are the point.

## How it was checked

- New `tests/test_brainstorm_commits.py`: a real temporary repository with
  an uncommitted change and an untracked file runs every brainstorm stage
  through a fake agent (which also writes a stray file). Afterwards the
  user's work and the stray file are still uncommitted, and every
  brainstorm commit touches brainstorm paths only. This test failed before
  the fix. Also covered: chat turns still commit the agent's edits, and
  `commit_paths` with a path that was never written.
- Full suite green.
