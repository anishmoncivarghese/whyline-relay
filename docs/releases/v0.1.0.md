# whyline-relay 0.1.0

First release. `whyline-relay` runs a Markdown plan through an unattended Codex-to-Claude loop: Codex implements a task, Claude reviews it and commits, and the relay routes every turn on whyline's own handoff record. It never pushes, and never passes a permission-bypass flag.

## What it does

- `start` runs each unchecked task through implement, review and a verified commit, then ticks the plan and commits only the plan file, leaving the tree clean.
- `resume`, `status` and `stop` cover pauses; Ctrl+C stops the running agent and saves resumable state; `resume` re-enters at the decision point the handoff record shows.
- `init` writes the relay's permissions (`.whyline/relay/claude-settings.json`), prompt templates and configuration. It needs whyline installed and `whyline init` run first.

## What was checked

- The code was built by Codex and reviewed and committed by Claude, task by task; the plan and the reviews are in the whyline repository under `docs/superpowers/` and `.whyline/decisions.md`.
- 140 tests, on Linux and macOS, Python 3.11 and 3.13, with fake agents only: the suite never launches a real `codex` or `claude`.
- Run for real against `codex-cli 0.155.1` and Claude Code `2.1.278` on macOS, following the README, with a two-task plan.

## Things to know

- **Codex is not sandboxed from committing.** Its sandbox does not stop `git commit` (measured on `codex-cli 0.155.1`); the prompt forbids it and the relay pauses if HEAD moves.
- **The permission allowlist is a convenience, not a security boundary.** Entries such as `uv run`, `npm` and `npx` execute arbitrary project code. Run unattended relays on an isolated branch of a repository that holds no valuable secrets.
- **The reviewer cannot run your tests until you allow the command** in `.whyline/relay/claude-settings.json`.
- Tested on macOS with the two CLI versions above. Windows is untested.
